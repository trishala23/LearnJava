Java 25 Features

The newest long-term support release: it lowers the barrier for beginners (a one-line "Hello, World!") while finalizing tools — scoped values, flexible constructors — that mostly matter once you're writing serious concurrent code.

1. Compact Source Files & Instance Main Methods

Finalized from a multi-release preview: a first Java program no longer needs a class, an access modifier, `static`, or a `String[]` parameter.

public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
void main() {
    println("Hello, Java!");   // System.out.println is implicitly imported
}
Still real Java: the compiler wraps this in an implicit, unnamed class behind the scenes — it's meant to flatten the learning curve and shrink scripts, not to replace normal classes in real applications.

2. Module Import Declarations

Import every exported package of a module in one line — handy in compact source files and for exploratory/scripting code.

import module java.base;   // pulls in java.util, java.io, java.lang, etc.

void main() {
    List<Integer> nums = new ArrayList<>(List.of(3, 1, 2));
    Collections.sort(nums);
    println(nums);
}
A module import can't be used to selectively hide/rename types — for a shared library's public API you'll still want targeted import statements to keep things explicit.

3. Flexible Constructor Bodies

Before Java 25, this(...)/super(...) had to be the very first statement in a constructor. Now you can validate or compute values first — as long as you don't touch the instance being constructed before calling the super constructor.

class PositiveNumber {
    private final int value;

    PositiveNumber(int value) {
        if (value <= 0) {
            throw new IllegalArgumentException("must be positive: " + value);
        }
        this.value = value;
    }
}

class Base {
    Base(int x) { System.out.println("Base got " + x); }
}

class Derived extends Base {
    Derived(int raw) {
        int normalized = Math.max(raw, 0);   // allowed before super() now
        super(normalized);
        System.out.println("Derived ready");
    }
}

4. Scoped Values (finalized)

A safer, immutable alternative to ThreadLocal — a value is bound for the duration of one call, automatically visible to everything it calls (including child virtual threads), and automatically un-bound when that call returns.

static final ScopedValue<String> CURRENT_USER = ScopedValue.newInstance();

void handleRequest(String user) {
    ScopedValue.where(CURRENT_USER, user)
               .run(() -> processOrder());   // CURRENT_USER only visible inside run()
}

void processOrder() {
    System.out.println("Processing for " + CURRENT_USER.get());
}
Why not just ThreadLocal? ThreadLocal values are mutable, can leak between pooled threads if you forget to clear them, and don't propagate cheaply to the huge numbers of virtual threads a structured-concurrency task might spawn. Scoped values are write-once, automatically scoped, and designed with virtual threads in mind.

5. Structured Concurrency (still in preview)

Continuing from Java 21's preview, the API keeps evolving — the core idea is unchanged: subtasks forked in a scope are joined together, and failure in one cancels the rest.

try (var scope = StructuredTaskScope.open(Joiner.awaitAllSuccessfulOrThrow())) {
    Subtask<String> user  = scope.fork(() -> fetchUser());
    Subtask<String> order = scope.fork(() -> fetchOrder());

    scope.join();
    render(user.get(), order.get());
}
Still a preview feature in Java 25 (API shape has changed between 21 and 25) — expect it to keep moving until it's finalized in a future release.

6. Primitive Types in Patterns, instanceof, and switch (preview)

Pattern matching (see Java 21) extends to primitives — no more manual boxing just to fit a case label.

static String classify(int code) {
    return switch (code) {
        case 0 -> "zero";
        case int c when c < 0 -> "negative";
        case int c -> "positive: " + c;
    };
}

Object o = 42;
if (o instanceof int i) {
    System.out.println("int value: " + i);
}

7. Runtime & GC Improvements

Java 25 isn't only new syntax — it tightens up the runtime itself.

ChangeWhy it matters
Generational Shenandoah (production)Applies generational collection to the low-pause Shenandoah GC, improving throughput on top of its already-tiny pause times.
Compact Object HeadersShrinks the per-object header from 12–16 bytes toward 8, reducing heap footprint across the board.
Ahead-of-Time command-line ergonomicsMakes AOT-cached startup (introduced in 24) easier to opt into without hand-tuned flags.
Removal of the 32-bit x86 portThe JDK build matrix drops legacy 32-bit x86 — a housekeeping change, not something app code needs to react to.
