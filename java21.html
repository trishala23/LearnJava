Java 21 Features

Records, sealed hierarchies, and pattern matching finally click together — plus virtual threads, which change how you think about concurrency entirely.

1. Records (Java 16+, everywhere by 21)

A record is an immutable data carrier: constructor, accessors, equals/hashCode/toString generated for you.

final class Point {
    private final int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }
    int x() { return x; }
    int y() { return y; }
    @Override public boolean equals(Object o) { /* ~10 lines */ }
    @Override public int hashCode() { /* ... */ }
    @Override public String toString() { /* ... */ }
}
record Point(int x, int y) { }

Point p = new Point(3, 4);
System.out.println(p);        // Point[x=3, y=4]
System.out.println(p.x());    // 3

2. Sealed Classes & Interfaces

A sealed type declares exactly which classes may extend/implement it — giving the compiler (and your pattern matches) a closed, exhaustive set of cases.

sealed interface Shape permits Circle, Square, Triangle { }

record Circle(double radius) implements Shape { }
record Square(double side) implements Shape { }
record Triangle(double base, double height) implements Shape { }

3. Pattern Matching for switch & Record Patterns

Combine a sealed hierarchy with pattern matching and the compiler can verify every case is handled — no default needed.

double area = switch (shape) {
    case Circle c -> Math.PI * c.radius() * c.radius();
    case Square s -> s.side() * s.side();
    case Triangle t -> 0.5 * t.base() * t.height();
    // no default needed — Shape is sealed and every case is covered
};

// Record patterns (Java 21): destructure directly in the case label
String describe(Object obj) {
    return switch (obj) {
        case Circle(double r) when r > 10 -> "Big circle, r=" + r;
        case Circle(double r) -> "Circle, r=" + r;
        case null -> "Nothing here";
        default -> "Some other shape";
    };
}

4. Virtual Threads (Project Loom)

Platform threads are expensive (each wraps an OS thread, ~1MB stack). Virtual threads are cheap, JVM-managed threads — you can spin up millions of them, one per request, with plain blocking-style code.

Platform thread
heavy, OS-scheduled
Virtual thread
light, JVM-scheduled onto a small pool of carrier threads
ExecutorService pool = Executors.newFixedThreadPool(200);
for (int i = 0; i < 10_000; i++) {
    pool.submit(() -> handleRequest());   // queues once threads run out
}
try (ExecutorService vExec = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) {
        vExec.submit(() -> handleRequest()); // one virtual thread each — cheap
    }
} // waits for all tasks on close
Mental model: virtual threads don't make CPU-bound code faster — they remove the cost of blocking (I/O waits) so a server can handle far more concurrent connections with ordinary, readable, blocking-style code instead of reactive/async chains.

5. Sequenced Collections

A new SequencedCollection/SequencedMap interface family gives every ordered collection a consistent way to reach both ends.

List<Integer> list = new ArrayList<>(List.of(1, 2, 3));
list.getFirst();     // 1
list.getLast();      // 3
list.addFirst(0);     // [0, 1, 2, 3]
list.reversed();      // a reversed VIEW, no copy needed

6. Text Blocks

Multi-line string literals (standardized in Java 15) — no more "...\n" + chains for JSON, SQL, or HTML.

String json = """
    {
      "name": "Duke",
      "language": "Java"
    }
    """;

7. Structured Concurrency (preview)

Treats a group of related tasks running on different threads as a single unit of work — if one subtask fails, the others are cancelled automatically.

try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    Supplier<String> user  = scope.fork(() -> fetchUser());
    Supplier<String> order = scope.fork(() -> fetchOrder());

    scope.join();            // wait for both
    scope.throwIfFailed();    // propagate any failure

    render(user.get(), order.get());
}
Preview feature in Java 21 — API surface may still change in later releases.
