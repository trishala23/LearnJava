// Fail-fast iteration: mutating a collection while iterating throws
// ConcurrentModificationException — unless you use the Iterator's own remove()
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (it.next().isEmpty()) it.remove(); // safe
}

2. Generics

Compile-time type safety without casting — implemented via type erasure (generic type info doesn't exist at runtime).

class Box<T> {
    private T value;
    void set(T value) { this.value = value; }
    T get() { return value; }
}

// Bounded wildcards — PECS: Producer Extends, Consumer Super
void printAll(List<? extends Number> nums) {   // producer: read-only, any Number subtype
    for (Number n : nums) System.out.println(n);
}
void addIntegers(List<? super Integer> list) {  // consumer: safe to write Integers
    list.add(42);
}
Type erasure means: you can't do new T(), can't check instanceof List<String>, and can't have two overloads that differ only by generic type parameter.

3. Concurrency

From raw Threads to structured task management.

class Counter {
    private int count = 0;
    synchronized void increment() { count++; } // one thread at a time
}

Thread t = new Thread(() -> System.out.println("Running"));
t.start();
t.join(); // wait for it to finish
ExecutorService pool = Executors.newFixedThreadPool(4);
Future<Integer> future = pool.submit(() -> 2 + 2);
System.out.println(future.get()); // blocks until done
pool.shutdown();
CompletableFuture.supplyAsync(() -> fetchUser())
    .thenApply(User::getName)
    .thenAccept(System.out::println)
    .exceptionally(ex -> { System.out.println("Failed: " + ex); return null; });
ReentrantLock lock = new ReentrantLock();
lock.lock();
try {
    // critical section
} finally {
    lock.unlock(); // always release in finally
}
synchronized vs Lock: ReentrantLock adds tryLock (non-blocking), fairness policies, and interruptible waits that the synchronized keyword can't express.

6. SOLID Principles

Five design principles (Robert C. Martin, "Uncle Bob") for keeping object-oriented code understandable, flexible, and maintainable — foundational to why the design patterns below are shaped the way they are.

LetterPrincipleOne-line idea
SSingle ResponsibilityA class should have only one reason to change.
OOpen/ClosedOpen for extension, closed for modification.
LLiskov SubstitutionA subclass must be usable anywhere its superclass is, without surprises.
IInterface SegregationDon't force a class to implement methods it doesn't need.
DDependency InversionDepend on abstractions, not concrete implementations.
 
// ✗ Violates SRP — User has two reasons to change: its data shape,
// and how/where it gets persisted.
class User {
    String name, email;

    void saveToDatabase() {
        System.out.println("Saving " + name + " to the database...");
    }
}

// ✓ One responsibility each. A storage change only touches UserRepository;
// a data-shape change only touches User.
class User {
    String name, email;
}

class UserRepository {
    void save(User user) {
        System.out.println("Saving " + user.name + " to the database...");
    }
}
// ✗ Violates OCP — every new shape means editing this method again.
class AreaCalculator {
    double area(Object shape) {
        if (shape instanceof Circle c) return Math.PI * c.radius * c.radius;
        if (shape instanceof Square s) return s.side * s.side;
        // adding Triangle means coming back here and risking the existing cases
        throw new IllegalArgumentException("Unknown shape");
    }
}

// ✓ Open for extension, closed for modification — AreaCalculator never
// changes again; each new shape is just a new class.
interface Shape { double calculateArea(); }

class Circle implements Shape {
    double radius;
    Circle(double radius) { this.radius = radius; }
    public double calculateArea() { return Math.PI * radius * radius; }
}

class Square implements Shape {
    double side;
    Square(double side) { this.side = side; }
    public double calculateArea() { return side * side; }
}

class AreaCalculator {
    double total(List<Shape> shapes) {
        return shapes.stream().mapToDouble(Shape::calculateArea).sum();
    }
}
class Bird {
    void fly() { System.out.println("Flying high!"); }
}

class Sparrow extends Bird { }      // fine — a Sparrow really can fly

class Penguin extends Bird {          // ✗ violates LSP
    @Override
    void fly() {
        throw new UnsupportedOperationException("Penguins can't fly!");
    }
}

void letItFly(Bird bird) { bird.fly(); }

letItFly(new Sparrow());    // works as callers expect
letItFly(new Penguin());     // blows up at runtime — substituting a subclass broke the caller

// Fix: don't bake "can fly" into the base class at all. Make Flyable its
// own interface implemented only by birds that actually fly — then a
// Penguin is just a Bird, and no caller ever assumes it can fly.
// ✗ Violates ISP — a fat interface forces Robot to "implement" eat(),
// which it has no sensible behavior for.
interface Worker {
    void work();
    void eat();
}

class Robot implements Worker {
    public void work() { System.out.println("Robot working..."); }
    public void eat() { throw new UnsupportedOperationException("Robots don't eat!"); }
}

// ✓ Split into focused interfaces — implement only what applies to you.
interface Workable { void work(); }
interface Eatable { void eat(); }

class Human implements Workable, Eatable {
    public void work() { System.out.println("Human working..."); }
    public void eat() { System.out.println("Human eating..."); }
}

class Robot implements Workable {
    public void work() { System.out.println("Robot working..."); }
    // no eat() to fake — Robot was never forced to have one
}
// ✗ Violates DIP — Car is welded to one concrete engine; swapping
// engines (or unit-testing Car without a real V8) means editing Car itself.
class V8Engine {
    void start() { System.out.println("V8 engine roaring to life"); }
}

class Car {
    private V8Engine engine = new V8Engine();
    void start() { engine.start(); }
}

// ✓ Car depends on an abstraction — any Engine will do, injected from outside.
interface Engine { void start(); }

class V8Engine implements Engine {
    public void start() { System.out.println("V8 engine roaring to life"); }
}

class ElectricEngine implements Engine {
    public void start() { System.out.println("Electric motor humming to life"); }
}

class Car {
    private final Engine engine;
    Car(Engine engine) { this.engine = engine; }   // dependency injected via constructor
    void start() { engine.start(); }
}

new Car(new V8Engine()).start();
new Car(new ElectricEngine()).start();   // swapped with zero changes to Car
SOLID and interfaces go hand in hand: OCP, ISP, and DIP above are only possible because Java has interfaces — see Interfaces for the language mechanics, and Design Patterns just below for named, reusable shapes (Strategy, Factory, Dependency Injection) that are really SOLID applied consistently.

7. Design Patterns

enum Singleton {                  // enum singleton: thread-safe, serialization-safe
    INSTANCE;
    void doWork() { System.out.println("Working"); }
}
Pizza pizza = new Pizza.Builder()
    .size("Large")
    .topping("Cheese")
    .topping("Olives")
    .build();
interface Shape { void draw(); }

class ShapeFactory {
    static Shape create(String type) {
        return switch (type) {
            case "circle" -> new Circle();
            case "square" -> new Square();
            default -> throw new IllegalArgumentException(type);
        };
    }
}
interface Observer { void update(String event); }

class EventBus {
    private final List<Observer> observers = new ArrayList<>();
    void subscribe(Observer o) { observers.add(o); }
    void publish(String event) { observers.forEach(o -> o.update(event)); }
}

8. I/O & NIO

Classic java.io is stream-based and blocking; java.nio adds buffers, channels, and non-blocking selectors for scalable I/O.

// java.nio.file — the modern way to work with files
Path path = Path.of("data.txt");
List<String> lines = Files.readAllLines(path);
Files.walk(Path.of(".")).filter(Files::isRegularFile).forEach(System.out::println);
